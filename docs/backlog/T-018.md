## Goal
Make iteration L1 runnable by someone who has only cloned the repo: a root README, bash and PowerShell scripts, and VS Code configuration. Also make the web Dockerfile build the real SPA from /web, replacing the placeholder from T-003.

## Context
Read CLAUDE.md, docs/domain.md and relevant ADRs in docs/adr/. The user works in VS Code, may be on Windows, macOS or Linux, and would like to avoid Docker Desktop if there is an easy alternative. Scripts must be small and readable.

## Out of scope
Azure, Bicep, CI/CD, production images, Azurite (T-022).

## Acceptance criteria
- [ ] Root README.md covers: what the app is, prerequisites with install commands (Windows via winget in PowerShell, macOS via brew, Linux via apt), running everything in containers, the VS Code dev loop (SQL in Docker, API on the host with the debugger, web with the Vite dev server), URLs and ports, running tests and verify.sh, stopping and resetting (including deleting the SQL volume), and troubleshooting (port in use, SQL password policy, container runtime not running, Apple Silicon)
- [ ] Every command in the README is given for bash (macOS, Linux, WSL) and for PowerShell
- [ ] Running without Docker Desktop is documented with exact install and start commands: Docker Engine inside WSL2 (Windows), Colima (macOS), Docker Engine (Linux), and Podman as an alternative
- [ ] scripts/doctor.sh and scripts/doctor.ps1 (already in the repo) are referenced by the README and still pass
- [ ] scripts/local-up, local-down and local-reset exist as .sh and .ps1: they create `.env` from `.env.example` when missing, start, stop or reset the stack, and print the URLs; the .ps1 files run on Windows PowerShell 5.1 and PowerShell 7
- [ ] .vscode/extensions.json, tasks.json and launch.json: F5 starts the API with the debugger against the compose SQL, a task starts the web dev server, a task starts SQL only
- [ ] `docker compose up --build` serves the real SPA at http://localhost:3000, showing API status and database status
- [ ] The verifier follows the README literally from a fresh clone, once for the all-containers path and once for the VS Code dev-loop path, and records every deviation; every failing or missing step is fixed in the README

## Verification
`./scripts/verify.sh` green, plus the checks above evidenced in tests or PR notes.
