## Goal
Make iteration L1 runnable by someone who has only cloned the repo: a root README, bash and PowerShell scripts, and VS Code configuration. Also make the web Dockerfile build the real SPA from /web, replacing the placeholder from T-003.

## Context
Read CLAUDE.md, docs/domain.md and relevant ADRs in docs/adr/. The user works in VS Code, may be on Windows, macOS or Linux, and would like to avoid Docker Desktop if there is an easy alternative. Scripts must be small and readable.

## Out of scope
Azure, Bicep, CI/CD, production images, Azurite (T-022).

## Acceptance criteria
- [x] Root README.md starts with a "Fresh machine setup" section (Windows first), before anything else: winget commands for Git (`Git.Git`), .NET 10 SDK (`Microsoft.DotNet.SDK.10`), Node LTS (`OpenJS.NodeJS.LTS`), jq (`jqlang.jq`), VS Code (`Microsoft.VisualStudioCode`) with `code --install-extension` lines for the recommended extensions, Claude Code (`Anthropic.ClaudeCode`), and the container engine (Rancher Desktop, `SUSE.RancherDesktop`, in dockerd/moby mode; Podman and Docker Desktop as alternatives); then cloning to `C:\projects` (`mkdir C:\projects; cd C:\projects; git clone https://github.com/ptgc/foodplanner; cd foodplanner; git switch dev`); then a new terminal and `./scripts/doctor.ps1`. macOS (brew) and Linux (apt) follow. The verifier checks each winget id with `winget search --id <id> --exact` and marks any it could not check as unverified
- [x] Root README.md covers: what the app is, prerequisites, running everything in containers, the VS Code dev loop (SQL in Docker, API on the host with the debugger, web with the Vite dev server), URLs and ports, running tests and verify.sh, stopping and resetting (including deleting the SQL volume), and where secrets live and how to rotate them (`dotnet user-secrets` commands; reset deletes the volume), troubleshooting (port in use, SQL password policy, container runtime not running, Apple Silicon)
- [x] Every command in the README is given for bash (macOS, Linux, WSL) and for PowerShell
- [x] Running without Docker Desktop is documented with exact install and start commands: Docker Engine inside WSL2 (Windows), Colima (macOS), Docker Engine (Linux), and Podman as an alternative
- [x] scripts/doctor.sh and scripts/doctor.ps1 (already in the repo) are referenced by the README and still pass
- [x] scripts/local-up, local-down and local-reset exist as .sh and .ps1: local-secrets runs once: it generates a random SQL SA password that meets SQL Server policy and stores it with `dotnet user-secrets` in the Api project (`Sql:SaPassword`, and `ConnectionStrings:Default` for host runs against localhost,1433), skipping if already set. local-up reads it from user secrets, sets `MSSQL_SA_PASSWORD` for that process only, runs compose and prints the URLs; down and reset do the same. No `.env` with a password is ever written. Also add local-secrets to the script list; the .ps1 files run on Windows PowerShell 5.1 and PowerShell 7
- [ ] .vscode/extensions.json, tasks.json and launch.json: F5 starts the API with the debugger against the compose SQL, a task starts the web dev server, a task starts SQL only
- [x] `docker compose up --build` serves the real SPA at http://localhost:3000, showing API status and database status
- [x] The verifier follows the README literally from a fresh clone, once for the all-containers path and once for the VS Code dev-loop path, and records every deviation; every failing or missing step is fixed in the README
