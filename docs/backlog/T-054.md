## Goal
The screens for the session-only "Add to Oda cart" flow in docs/specs/T-053-oda-cart-session.md (aligned 2026-11-20 with the architect's answers to Q-024, Q-025, Q-032 and Q-033). The earlier scope ("map ingredients to products") is dropped: T-053 stores no product mapping, and choosing preferred products is later work (T-052, T-114).

## Context
Read CLAUDE.md, ADR 0008 (Decision 2026-11-20), the T-053 spec and the T-051 export screens.
- Button "Add to Oda cart" on a week's shopping list, shown only to Adults (Owner, Adult) and never in kid mode.
- Confirmation that lists exactly what will be sent (the unchecked "To buy" items; "Check you have" staples are not sent). It also says that Oda opens for sign-in, that one pack of each item is added, that nothing is ordered or paid, and that sending twice adds twice.
- On confirm, call `oda/start` and go to the returned Oda sign-in URL.
- The callback page on Foodplanner's own origin reads `code`/`state` (or `error`) from the URL, calls `oda/cart` once and never retries it (cart quantities are deltas), and then removes the code from the address bar.
- The result screen shows:
  - what was added (item and Oda product name, quantity)
  - what was not added, with the reason
  - Oda's cart messages
  - a link to the Oda cart for final swaps, fixes and payment
  - a note pointing to Privacy & security in Oda when `connectionClosed` is false
- On failure, show what was already added and offer the T-051 text export right there.
- The UI never stores Oda data (no local storage of products, codes or tokens).

## Out of scope
Picking a preferred product per ingredient (T-052) and "usually bought" hints (T-114).

## Acceptance criteria
- [ ] The button is visible only to Adults and hidden in kid mode; the confirmation lists exactly what will be sent
- [ ] The callback page calls `oda/cart` exactly once (no retry on reload or back navigation) and clears the code from the URL
- [ ] The result shows added, not added with reasons, cart messages, the Oda cart link and the connection-not-closed note when needed; failure offers the text export
- [ ] Nothing from Oda is written to browser storage
- [ ] Works at 390px with 44px touch targets
- [ ] Playwright tests with a faked Oda API (no real Oda calls): success, partial, denied at Oda, failure with fallback
