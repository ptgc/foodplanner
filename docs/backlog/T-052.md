# T-052: Preferred Oda product per ingredient

## Goal
Let an Adult say which Oda product the household wants for an ingredient ("this kind of cherry tomatoes, not that one"; the same for mayonnaise, cheese and so on), so that the next "Add to Oda cart" adds the right product from the start instead of the first search hit. Earlier scope (a generic `IngredientProductMapping` to a provider SKU, before T-053) is replaced by this.

## Context
Read CLAUDE.md, docs/domain.md, ADR 0008, Q-024, Q-025, Q-032 (answer) and docs/specs/T-053-oda-cart-session.md.
- Q-032 answer: keep only the Oda product id per (household, ingredient), set by an Adult. No name, price, brand or search result is stored.
- Oda has no SKU/EAN (T-001 Phase B), so the key is Oda's product `id`.
- Product names and prices for showing the choice come from Oda during a session-only connection (Q-024, Q-025); nothing beyond the id is kept.
- How an Adult picks the product (during or after a cart fill, from what was added, or from a search while connected) is a UX question for the spec; write the spec first.

## Out of scope
Using purchase history to guess the product (T-114). Prices and offers (T-107).

## Acceptance criteria
- [ ] Spec written and agreed (how and when an Adult picks a product while connected to Oda)
- [ ] Preferred product is household-scoped (`ITenantEntity`) and covered by the tenant-isolation suite; it holds only the Oda product id per ingredient
- [ ] Endpoints to list, set and clear a preference, Adult only (Child and kid mode `403`)
- [ ] The T-053 cart fill uses the preferred product when it is available, falls back to search when it is unavailable or gone, and reports that in the result
- [ ] Nothing else from Oda is stored; `./scripts/verify.sh` green
