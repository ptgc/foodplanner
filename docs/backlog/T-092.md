## Goal
Architect request 2026-10-29: a household has a set of regular weekly groceries (bread, milk, cheese, ...), configured on the household page. On the shopping list, one button "Add weekly groceries" puts them on the week's list.

## Context
Read docs/domain.md (shopping list T-031, manual items, reconciliation, store sections T-085, offline cache T-088), the household settings screen. Decisions by the orchestrator (the architect can change them; document them in docs/domain.md):
- A weekly grocery item is structured (rule 5): an ingredient (catalog or own) with an optional quantity + unit. So it sorts by store section like everything else. No free text.
- Tenant entity (`ITenantEntity`), in the isolation suite. Max 50 items per household. Adult/Owner manage the set (policy-based); any member can press the button.
- The button adds the items to the chosen week as their own kind of item (e.g. `Origin = Weekly`), never removed by the plan reconciliation. If the same ingredient is already on the list from recipes, the weekly amount is added to it (same unit dimension) or shown as an extra line; no duplicate item rows.
- Idempotent per week: pressing again adds only what is missing (does not double the amounts); a weekly item the user removed from this week stays removed until pressed again.
- Weekly items can be checked off and removed one by one like manual items. Live update (SignalR) and offline cache as for the rest of the list (bump `CACHE_SCHEMA` if the response shape changes).

## Out of scope
Automatic adding every week without a tap; Oda; per-store weekly sets.

## Acceptance criteria
- [ ] Household page: list, add (ingredient search + optional amount), edit, remove weekly groceries; 390 px, touch targets ≥ 44 px; nb + en
- [ ] Shopping list: "Add weekly groceries" button (disabled with a hint when the set is empty); items land in their store sections
- [ ] Merge with recipe items as decided above; pressing twice changes nothing; regenerating from the plan keeps weekly items
- [ ] Tenant isolation test for the new entity; policy tests (Child cannot edit the set)
- [ ] Domain unit tests for adding/merging; API tests; e2e: configure bread + milk, press the button, both appear under their sections, press again, no duplicates
