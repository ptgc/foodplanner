## Goal
Architect request 2026-10-28: an adult sets up the household's weekly food plan rules, e.g. "each week at least one fish and one vegetarian dinner". As dinners are picked for the week (by kids or adults), recipes that would make the rules impossible to meet are filtered out (or marked), so the finished week always satisfies the rules.

Example: rules "≥ 1 Fish, ≥ 1 Vegetarian", 7 dinners. After 5 meat dinners are picked, the 2 remaining days can only take Fish or Vegetarian recipes; meat recipes are filtered out for those days.

## Context
Read docs/questions/Q-021.md, T-089 (food type), the T-026 spec (kid profiles; whether kids pick dinners for days or only like dishes is Q-020/Q-021), docs/domain.md (meal plan). The feasibility check is pure Domain logic: given the rules, the days left and the types already planned, which types can still be added without making the rules unmeetable. Thorough unit tests (min counts, max counts if decided, fewer days than rules, a recipe with several types).

## Out of scope
Nutrition, calories, budget rules.

## Acceptance criteria
- [ ] Household rules: per food type a minimum per week (and maximum, if decided in Q-021); Adult/Owner manage them (policy-based); tenant entity in the isolation suite
- [ ] Pure Domain feasibility function with thorough unit tests
- [ ] Planning API returns, for a day, which recipes are allowed (or flags the rest with a reason); the server refuses a pick that makes the week infeasible when the rule is "enforced" (per Q-021)
- [ ] Kid UI and adult planner show only allowed recipes (or greyed out with a short reason for adults)
- [ ] e2e: rules ≥1 fish ≥1 vegetarian, pick meat for 5 days, only fish/vegetarian offered for the last 2
