## Goal
Throwaway console app (in /spikes/oda, not part of main solution) that searches products, logs in, and adds items to a cart. Document findings in ADR 0008 and set it to accepted with verdict feasible/fragile/not feasible. Do not commit credentials.

## Context

Update 2026-10-27 (architect): Oda offers a hosted MCP server at https://oda.com/mcp (info page https://oda.com/mcp?demo&lang=en). Remote MCP, sign-in with the user's Oda account via browser redirect (no API key), ~25 tools: product search/similar products, categories/brands, Oda recipes, cart view/edit/clear (+ link to pay in the shop), shopping and dinner lists, order history/delivery tracking, addresses and delivery slots. No checkout/payment via MCP. Written for individuals connecting their own AI assistant; third-party app use is not stated. The spike should start here: (1) read Oda's terms of use and the server manifest — may an app like foodplanner act as the MCP client for a household? (2) how sign-in/token works for a non-assistant client (MCP OAuth, dynamic client registration?), token lifetime and storage (Key Vault / user secrets, rule 7); (3) product search quality for our catalog ingredients (nb names) and cart-edit semantics; (4) compare with the assistant-bridge route (foodplanner exposes the list via its text export or its own MCP server; the user's assistant fills the Oda cart). Update ADR 0008 with the verdict.
Read CLAUDE.md, docs/domain.md and relevant ADRs in docs/adr/.
