## Goal
Throwaway console app (in /spikes/oda, not part of main solution) that searches products, logs in, and adds items to a cart. Document findings in ADR 0008 and set it to accepted with verdict feasible/fragile/not feasible. Do not commit credentials.

## Context

Update 2026-10-27 (architect): Oda offers a hosted MCP server at https://oda.com/mcp (info page https://oda.com/mcp?demo&lang=en). Remote MCP, sign-in with the user's Oda account via browser redirect (no API key), ~25 tools: product search/similar products, categories/brands, Oda recipes, cart view/edit/clear (+ link to pay in the shop), shopping and dinner lists, order history/delivery tracking, addresses and delivery slots. No checkout/payment via MCP. Written for individuals connecting their own AI assistant; third-party app use is not stated. The spike should start here: (1) read Oda's terms of use and the server manifest — may an app like foodplanner act as the MCP client for a household? (2) how sign-in/token works for a non-assistant client (MCP OAuth, dynamic client registration?), token lifetime and storage (Key Vault / user secrets, rule 7); (3) product search quality for our catalog ingredients (nb names) and cart-edit semantics; (4) compare with the assistant-bridge route (foodplanner exposes the list via its text export or its own MCP server; the user's assistant fills the Oda cart). Update ADR 0008 with the verdict.
Read CLAUDE.md, docs/domain.md and relevant ADRs in docs/adr/.

## Phase B (manual, architect at the computer)
The spike needs a browser sign-in to your own Oda account, so it cannot run unattended.

1. Get the spike code. It is in the T-001 worktree, if that still exists:
   `git worktree list | grep T-001`
   If the worktree is gone, check out the branch into a new one:
   `git worktree add ../fp-t001 task/T-001-oda-feasibility-spike`
   In the commands below, `<SPIKE>` is `<that worktree>/spikes/oda`. It was `C:/Project/foodplanner/.claude/worktrees/agent-a258d90d5e8ebcda5/spikes/oda` on 2026-10-31.
2. In the Claude Code prompt, run these one at a time (the `!` prefix puts the output into the session, so the orchestrator can resume the T-001 agent with it):
   ```
   ! dotnet run --project <SPIKE> -- login            # browser opens; sign in to Oda and approve. Do not paste the sign-in URL anywhere.
   ! dotnet run --project <SPIKE> -- tools
   ! dotnet run --project <SPIKE> -- search melk
   ! dotnet run --project <SPIKE> -- search-catalog   # optional: ~20 searches for our ingredient names; skip it to keep well clear of the ToS "collecting" wording
   ! dotnet run --project <SPIKE> -- cart
   ! dotnet run --project <SPIKE> -- search smør      # pick one cheap product id
   ! dotnet run --project <SPIKE> -- add <productId> 1
   ! dotnet run --project <SPIKE> -- cart
   ! dotnet run --project <SPIKE> -- clear-test-items  # removes only what the spike added
   ! dotnet run --project <SPIKE> -- cart
   ```
   Optional: run `cart` again more than an hour later. If the refresh works, it prints "Access token expired; refreshing.".
3. Tell the orchestrator whether anything already in your cart changed. Report any "FAILED: ..." message in full.
4. Clean up afterwards: `dotnet user-secrets clear --project <SPIKE>`, and revoke the connection in Oda under Privacy & security.
