## Goal
Make the local stack usable with a real schema and a ready-to-use account, without Google login (T-010 postponed) and without anything in Azure.
1. Apply EF Core migrations to the local compose database with an explicit command (`scripts/local-migrate.sh` and `.ps1`, using a migration bundle or `dotnet ef database update` against the user-secrets connection string). `local-up` runs it after sql-init and before api starts, or as a compose one-shot `migrate` service. The API still never migrates at startup (CLAUDE.md).
2. Seed one local admin: a confirmed user who is Owner of a household named "Home". `scripts/local-secrets` generates the admin email (`admin@foodplanner.local`) and a random password that meets the T-009 password rules and stores them in .NET user secrets for the Api project (`Seed:AdminEmail`, `Seed:AdminPassword`), skipping if already set. A seed command (script or Development-only hosted step) creates the user and household if they do not exist. Idempotent.

## Context
Read CLAUDE.md, docs/domain.md, ADR 0004, 0005, the T-008, T-009 and T-011 specs, and docs/questions/Q-010.md. Architect decision Q-010: local-only, secrets only in user secrets, seeded admin instead of Google login for now.

## Out of scope
Google login (T-010), production seeding, Azure, CI, a register screen.

## Acceptance criteria
- [ ] `local-migrate` (sh and ps1) applies all migrations to the compose database; running it twice is a no-op; `__EFMigrationsHistory` lists every migration (shown with sqlcmd)
- [ ] `local-up` applies migrations before api serves requests; a fresh clone + `local-up` gives a working schema; API startup still does not migrate (existing test stays green)
- [ ] `local-secrets` stores `Seed:AdminEmail` and `Seed:AdminPassword` in user secrets, never prints the password, skips if set; README section "Secrets" says how to read them (`dotnet user-secrets list --project src/Api`)
- [ ] After `local-up`, `POST /api/auth/login` with the seeded credentials returns 204, `GET /api/auth/me` returns the admin, and the admin is Owner of household "Home"; seeding twice creates no duplicates
- [ ] Seeding never runs outside Development (test proves it); no credential in any tracked file (verify.sh grep stays green)
- [ ] README updated: run, reset (reset recreates schema and admin on next `local-up`), and where the admin login lives
