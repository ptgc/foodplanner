# T-088: Bug: shopping list crashes on a list cached by an older app version

Status: in-progress
Milestone: L3
Agent: implementer-frontend
Depends on: T-034, T-041, T-076, T-085
Migration: no
Branch: task/T-088-shopping-cache-schema-version

## Goal
Reported by the architect on 2026-10-28: after T-076/T-085 the shopping page crashed with `TypeError: Cannot read properties of undefined (reading 'map')` (shopping route chunk, `item.alternatives.map`, web/app/routes/shopping.tsx ~303). The API response is correct (items carry `alternatives` and `storeSection`). Likely cause (orchestrator, not confirmed): the offline copy in localStorage (`web/app/shopping/storage.ts`, `foodplanner.shopping.list.*`) was written by an app version before T-076 and is rendered before the fresh fetch; the cache has no schema version, so items without `alternatives` (and `storeSection`) reach the render.

## Context
Read web/README.md (offline, PWA), docs/domain.md (shopping list offline T-034, PWA T-041). Confirm the cause first (reproduce with an old-shape cached list). Check the other offline caches the same way (service worker runtime cache for recipes/tags, the check-off queue, any other localStorage/IndexedDB data the app renders before fetching).

## Out of scope
New offline features.

## Acceptance criteria
- [ ] Root cause confirmed and named in the task report
- [ ] Cached shopping lists carry a schema version; a cached list from another version (or with an unexpected shape) is ignored or migrated, never rendered raw; the check-off queue survives an app update
- [ ] Rendering tolerates missing optional arrays on items (no crash; alternatives/recipes/quantities treated as empty)
- [ ] The same review for other offline caches; fix any that can crash after an update
- [ ] Vitest: an old-shape cached list renders (or is dropped) without error; e2e or vitest covers the version bump
