## Result (2026-11-08)
Merged from task/T-112-dismissal-race-flake 9e0cb98. Root cause: a real lost renewal. `Dismiss` removed other labels' expired rows with a tracked `RemoveRange`; without a concurrency token the DELETE was by Id only, so a clean-up that had read an expired row could delete it after a concurrent renewal of that label had committed and answered 204. Fix: `DismissedAt` is an optimistic concurrency token (no schema change, no migration; one snapshot line), so the stale delete raises `DbUpdateConcurrencyException` and the existing retry loop re-reads. New test `A_cleanup_delete_of_a_row_that_was_renewed_meanwhile_fails_instead_of_losing_the_renewal` fails without the fix. Comment and docs/domain.md now say 5 attempts for list endpoints, 8 for dismiss.

Before the fix the test failed 8 of 20 runs; after, 30/30 (implementer) and 30/30 (verifier). Verifier PASS: verify green, `has-pending-model-changes` clean, column datetimeoffset(7) so no false conflicts, household/account deletes cascade in the database and never load these rows. Reviewer APPROVE, no blockers.
