## Goal
Decision Q-019 (option 3, stretch, plus the addendum): learn the order a household actually walks a store from the order items are checked off on the shopping list (`CheckedAt` is already stored per item). Learning is per store (T-087): the user picks the store they shop at, and each store learns its own order. Once a store has enough data, its learned order is offered to replace (or refine) that store's manual section order from T-087; the user stays in control (accept, reset, or keep the manual order).

## Context
Read docs/questions/Q-019.md, T-085 and T-087. Open design points to settle (raise a question first if unsure): learn per section only or also per ingredient within a section; how many shopping trips before the learned order is trusted; ignore check-offs done at home or in a burst (e.g. ticking everything at once after shopping); how a learned order and the manual order (T-087) combine; let the user reset or turn it off; keep the logic pure in Domain.

## Out of scope
Store maps, location tracking (the store is picked by the user, not detected).

## Acceptance criteria
- [ ] Decisions on the open points recorded (question file) before implementation
- [ ] Pure Domain learner with unit tests (stable with noise, ignores bursts, falls back to the store's manual order, then the T-085 order)
- [ ] Check-offs are recorded per chosen store; the learned order is per store
- [ ] With enough trips, the store's list uses (or offers) the learned order; the user can reset to the manual order
