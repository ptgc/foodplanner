## Goal
Implement an Oda IShoppingListExporter that, on an Adult's tap, signs in to the household's shared Oda account for that one action, adds the list's items to the Oda cart and closes the connection, per the T-001 findings and the session-only decision (Q-024, Q-025). Nothing from Oda is stored. See the spec.

## Acceptance criteria
- [ ] Session-only: no Oda access or refresh token or authorization code is persisted (database, cache, cookie, file) or logged, and the PKCE verifier is never logged and lives at most 10 minutes (where, see Q-033); the token lives only in memory for one action and is revoked at `/o/revoke_token/` when done, on error and on cancel (revoke and the disappearing connection in Oda's Privacy & security are checked in implementation, see the spec)
  - Not ticked: all behaviour is proven by tests against the fake Oda, but the four implementation checks against the real Oda (redirect URI accepted on our own origin, real revoke response, connection gone under Privacy & security, observed token lifetimes) need the registered client and a real account, so they are for the architect (see the task report).
- [x] Only Adults (Owner, Adult) can send; the user confirms before anything is added. A Child member and kid mode can never send to Oda, start an order or change the Oda cart (`403`; architect, 2026-11-03)
- [x] Nothing is ordered or paid automatically
- [x] Failures degrade to the share/copy export from T-050
