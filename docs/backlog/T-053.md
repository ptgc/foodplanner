## Goal
Implement an Oda IShoppingListExporter that, on an Adult's tap, signs in to the household's shared Oda account for that one action, adds the list's items to the Oda cart and closes the connection, per the T-001 findings and the session-only decision (Q-024, Q-025). Nothing from Oda is stored. See the spec.

## Context
Read CLAUDE.md, docs/domain.md and relevant ADRs in docs/adr/. Depends on the ADR 0008 verdict; raise a question about ToS if T-001 flagged one.

## Out of scope
Anything not listed in the goal. Raise a question instead of expanding scope.

## Acceptance criteria
- [x] Session-only: no Oda access or refresh token or authorization code is persisted (database, cache, cookie, file) or logged, and the PKCE verifier is never logged and lives at most 10 minutes (where, see Q-033); the token lives only in memory for one action and is revoked at `/o/revoke_token/` when done, on error and on cancel (revoke and the disappearing connection in Oda's Privacy & security are checked in implementation, see the spec)
  - Real-Oda check by the architect, 2026-11-22: (1) Oda accepted the redirect URI http://localhost:3000/oda/callback at registration; (2) and (3) two fills of 15 items each reported "connection closed True", and the Foodplanner client is not listed under Privacy & security in Oda afterwards (only the T-001 spike client from 2026-11-19 is); (4) token lifetimes were not observed: the token lives about 5 seconds per action and is revoked, so they do not matter for the session-only flow. Product choice is the first hit, so some items are not what the household buys: T-052 and T-114.
- [x] Only Adults (Owner, Adult) can send; the user confirms before anything is added. A Child member and kid mode can never send to Oda, start an order or change the Oda cart (`403`; architect, 2026-11-03)
- [x] Nothing is ordered or paid automatically
- [x] Failures degrade to the share/copy export from T-050
