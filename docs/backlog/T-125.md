## Goal
Non-blocking reviewer notes from T-118 (2026-11-22):
1. A multipart photo POST without the `X-XSRF-TOKEN` header makes the antiforgery check read the form with the default FormFeature (64 KB spool threshold) before the endpoint installs its in-memory FormFeature, so a forged request could briefly spool photo bytes to a temp file before the 400. Install the in-memory FormFeature (or reject a missing header) before any form read on that route.
2. `BufferBody = true` plus per-section rewind can hold about 2 x 44 MB per upload; consider `BufferBody = false` (sections are already in memory) and keep the concurrency gate.
3. Add an Api.Tests integration test that uploads a ~5 MB multipart body with the temp directory pointed at an empty folder and asserts no file appears.
4. The eval script prints only "HTTP 400" on API errors; show the error type and message (never the key).
5. When photo import is disabled, `photo-usage` returns the config default (2) instead of the household plan (Home shows 2, not unlimited); return the plan's values or nulls when disabled.
6. Web (T-119 review): pass `{ imageOrientation: "from-image" }` to createImageBitmap in web/app/photo/downsize.ts; release canvas memory after drawImage (iOS); downscale or decode thumbnails async in photo-picker.tsx; refetch photo usage after Cancel; tidy `type Loaded ={` and the layout shift of the lazy photo extras in import-review.tsx.
7. Abandoned photo-import drafts keep their crop blob until the household is deleted (no draft expiry). Decide expiry or cleanup (bounded by the 50-draft cap).
