## Goal
Several Playwright specs leave recipes, own ingredients, households or drafts behind in the shared local database (e.g. "E2E Import …", "E2E Photo size …", "Zqx…" ingredients, "Zz E2E …" households). Over time this grew the recipe list past one page and broke pwa.spec's assumptions (T-082). Make every spec clean up what it creates and make specs robust against existing data.

## Context
tests/e2e/** (fixtures: uniqueStamp, uniqueWeek, saveRecipe), the API delete endpoints (recipes, imports, households, own ingredients once T-079 lands), T-082's lesson: never assume a spec's data is on page one.

## Out of scope
Deleting the user's own (non-E2E) data.

## Acceptance criteria
- [x] Every spec deletes what it creates in `finally`/afterEach via the API (recipes, imports, own ingredients when T-079's delete exists, test households, shopping list/plan entries in unique weeks)
- [x] A one-off cleanup script (scripts/e2e-cleanup.sh/.ps1) removes leftovers matching the E2E naming patterns only, with a dry-run mode, for the seeded admin's households
- [x] After two full e2e runs, no new E2E-named rows remain (asserted by the cleanup script's dry run)
- [x] Specs find their data by search or id, never by list position
