## Goal
Architect decision 2026-10-29: on the 16 GB developer machine (Rancher/WSL VM capped at 5 GB, Claude Code runs inside VS Code), `./scripts/verify.sh` keeps getting killed for low memory during the .NET API tests (`Foodplanner.Api.Tests` ~1.4 GB on Windows, many test classes in parallel, each with its own host and connections) and sometimes during Vitest or Playwright. Reliability matters more than speed: a few minutes longer is fine, broken runs are not.

Make the local run memory-light by default, CI unchanged:
- Locally (no `CI` env var) verify.sh runs the .NET tests with limited parallelism (e.g. xUnit `maxParallelThreads` 1-2, test projects one after another) and Vitest with 1-2 workers; `scripts/e2e.sh` defaults to `--workers=1`.
- An env var overrides it both ways (e.g. `FP_TEST_PARALLEL=full` locally, or `low` in CI), documented in the README.
- Shut down the .NET build servers at the end of verify.sh (they hold ~0.5 GB after a run).
- Testcontainers: make sure one SQL Server container is reused per test run, no extra containers per class; check its memory limit.
