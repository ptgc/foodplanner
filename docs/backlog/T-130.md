## Goal
Architect request 2026-11-22 (easy start, time back): a "Sync with Oda" button. In one session-only Oda connection (ADR 0008 decision, nothing but product ids stored, Q-032), the app searches Oda for every ingredient used in the household's recipes (staples like salt only if the user opts in), reads `likely_to_buy` once, and returns a review list:
- "You usually buy this": a search hit that is in the usual set, pre-ticked;
- "Suggestion": the best available hit, not ticked;
- "Not found": left alone.
The user confirms; confirmed rows are saved as T-052 preferred products (ids only). Existing choices are never overwritten unless the user ticks them. Can be run again any time (e.g. after adding recipes). Product names live only in that response and the review screen state, never stored.

## Decisions (architect 2026-11-22, accepted recommendations)
Only ingredients used in recipes (+ opt-in staples); never overwrite existing choices unless ticked; `likely_to_buy` only, no order history for now (revisit if the hit rate is low). Oda calls: batched searches (10 queries per call) + one likely_to_buy, within Oda usage limits.
