## Goal
Let a household clean up wrong or outdated ingredients (architect request 2026-10-27, after the matprat.no import left clumsy own ingredients like "Torskefilet eller annen kokt"). Only the household's own ingredients; global catalog rows stay read-only.
- Delete an own ingredient that nothing uses.
- Merge an own ingredient into another ingredient (global or own): every reference (recipe ingredient lines, pantry items, shopping list items/quantities, import drafts) is moved to the target, then the source is deleted. Duplicate pantry rows / list items for the target are combined sensibly.
- Rename an own ingredient (same uniqueness rules as create).

## Out of scope

## Acceptance criteria
- [ ] DELETE own ingredient: 204 when unused; 409 ProblemDetails listing where it is used (counts per kind) when used; global or another household's ingredient → 403/404
- [ ] POST merge own ingredient into a target (global or own of the same household): references moved with tracked updates (no bulk ops), source deleted, all in one transaction; shopping lists regenerate cleanly afterwards; T-073 checks hold; another household's target refused
- [ ] PUT rename own ingredient with the existing duplicate-name rules (409 ingredient-exists)
- [ ] Adult/Owner only (Child 403); live sync signals sent if a shopping list changed
- [ ] Web: an "Ingredients" screen (in household settings or the recipes area) listing own ingredients with usage counts, rename, delete (confirm), merge (pick target via search, confirm); translated nb + en; 390px, 44px
- [ ] Tests: API (each path, isolation, concurrency of merge vs recipe edit), Vitest, Playwright (merge a clumsy own ingredient into a catalog one and see the recipe updated)
