## Goal
Architect decision 2026-10-28 (Q-019, addendum): a household can register the stores it shops at (e.g. "Rema Lade", "Kiwi sentrum") and set, per store, the order in which it walks the store sections (drag to reorder the T-085 sections). When shopping, the user picks the store; the shopping list is then sorted by that store's section order. Without a chosen store (or no stores at all), the fixed T-085 order applies.

## Context
Read docs/questions/Q-019.md, T-085, T-086, docs/domain.md (tenancy, shopping list). `Store` is household-owned (`ITenantEntity`; add to the tenant-isolation suite), name 1-100 chars unique per household, ordered section list (every T-085 section exactly once). The chosen store is a per-list (or per-user, decide and document) setting, not global. Managing stores: Adult or Owner; picking the store while shopping: any member. Mobile-first, reorder with touch-friendly controls (≥ 44 px; drag plus up/down buttons for accessibility).

## Out of scope
Learning the order (T-086); store locations, opening hours, Oda.

## Acceptance criteria
- [ ] CRUD for stores with a section order (API + a screen under the household settings); validation at the boundary (each section once)
- [ ] Shopping screen: store picker; the list follows the chosen store's order, headings move accordingly; the choice is remembered (as decided)
- [ ] Tenant isolation tests for `Store`; policy-based authorization
- [ ] Domain unit tests for ordering by a custom section order (fallback to T-085 order)
- [ ] e2e: create a store with dairy before produce, pick it, the list shows dairy first
