## Goal
Let a person sign in and out in the browser so the recipe and shopping screens have a logged-in household. Login form (email, password), logout, current user and active household shown in the shell, household switcher if the user has more than one, and a route guard that sends signed-out users to /login and back afterwards. Uses the T-009 auth endpoints (antiforgery token, cookie) and the T-011 household endpoints through the generated client only.

## Context
Read CLAUDE.md, ADR 0001 and 0004, the T-009 and T-011 specs and docs/questions/Q-010.md. The seeded admin from T-029 is the account used for manual testing. The browser origin is http://localhost (3000 in containers, 5173 with Vite); the auth cookie must work on both.

## Out of scope
Register, email confirmation, password reset screens, Google login (T-010), invites UI (T-045).

## Acceptance criteria
- [ ] /login signs in with email and password; wrong credentials show the generic error from the API without revealing which field was wrong
- [ ] Signed-out users visiting any app route are redirected to /login and returned to the original route after sign-in
- [ ] The shell shows the user's email and active household and has a logout button (44px targets, works at 390px)
- [ ] State-changing requests send the antiforgery token as T-009 requires (Vitest test on the client wrapper)
- [ ] Vitest tests for login success, failure and redirect; a Playwright test (T-027 harness) signs in as the seeded admin against the compose stack
- [ ] Works at http://localhost:3000 (containers) and http://localhost:5173 (Vite dev): sign in, reload, still signed in, logout

## Verification
`./scripts/verify.sh` green, plus the checks above evidenced with command output.
