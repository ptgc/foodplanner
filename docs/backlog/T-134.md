# T-134: Design update: a fresher, image-led, kid-friendly look

Status: todo
Milestone: M4
Agent: architect
Depends on: -
Migration: no
Branch: none (the architect picks the direction; the build goes on follow-up task branches)

## Goal
The app looks plain today. It needs a fresher look that is image-led and kid-friendly, so it is easy to start and enjoyable to use. This task settles the direction with the architect and then splits the work into small frontend tasks.

## Context
- Styling today is one hand-written file, `web/app/app.css` (about 570 lines). It has a few tokens on `:root` (`--fg`, `--bg`, `--accent` #1f6f43, `--error`, `--touch` 44px), the system font, light mode only and no dark mode. There is no component library and no Tailwind.
- Rules that stay: mobile-first at 390px, touch targets of at least 44px (CLAUDE.md rule 10), and the web bundle budget (backlog README, Q-031). New fonts or libraries count against that budget.
- Kid mode (T-091, T-105) already has its own styling. The design update should keep it, or deliberately restyle it.
- Do this before T-131 (Kom i gang and Help) builds many new screens, or plan it so T-131 picks up the new tokens.
- The axe check (T-135) should run on the new look, so contrast is checked automatically.

Open points for the architect (raise as a Q-xxx with options when the task starts):
1. Direction: colours, type, how large food images are, and the corner and card style. A mock-up of 2 or 3 key screens (week plan, recipe, shopping list) to choose from.
2. Dark mode now or later.
3. Own font (bundle cost) or the system font.
4. Rollout: tokens first, then screen by screen, or one big change.

## Out of scope
New features and changes to the flow. This task changes the look only, unless the architect asks for more.

## Acceptance criteria
- [ ] The design direction is chosen by the architect (question answered, mock-ups approved)
- [ ] Design tokens are written down (colours, type scale, spacing, radius, shadows), with contrast that passes WCAG AA
- [ ] Follow-up frontend tasks are added to the backlog in order, each small enough for one branch
- [ ] The `frontend-screen` skill points to the tokens
