## Goal
Enforce Q-012 option 3 in one place: before SaveChanges, every added or modified foreign key on a tenant or catalog entity must point to a row in the same household or to a global row. Handlers keep resolving ids through the filtered sets (option 1); this is the backstop.

## Context
Read CLAUDE.md, docs/domain.md (Tenancy section, CrossHouseholdLinks), docs/questions/Q-012.md, and the T-008 save interceptor. Derive the checks from the EF model so new entities are covered automatically. Keep the extra queries per save small (batch per principal type).

## Out of scope
Composite database foreign keys (Q-012 option 2).

## Acceptance criteria
- [ ] Saving a row that references another household's row throws a tenancy violation, for every tenant/catalog FK in the model (test derived from the model, like the T-012 coverage test)
- [ ] References to global rows and own rows still save
- [ ] Existing API behaviour is unchanged (handlers still return their 400s before the guard is reached)
- [ ] Query count per save is bounded and documented
