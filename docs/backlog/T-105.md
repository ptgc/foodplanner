## Goal
T-091 shows the normal adult shopping list in kid mode (reached by the cart icon). The T-026 spec's UI sketch asks for a kid view: product pictures where the catalog has them, no adult controls (generate, weekly groceries, pantry, export, manual add) and as little text as possible. Found in the T-091 review (2026-11-02).

## Decision (architect, 2026-11-03)
Kids do not really need the shopping list, but they may look at it to see what is there. **Read only in kid mode**: no check-off, no adding (stricter than the earlier recommendation of check-off only).

Today (T-091) kid mode gets the adult list, and the API lets every member, kid mode included, generate, add weekly groceries, add and remove manual items, check off, choose a store and change the pantry (domain.md, shopping list and pantry permissions). This task closes that for kid mode.

Scope: kid mode only (the 4-8 year old profiles of T-026). A Child **member** with their own account keeps today's rights (check off, add, pantry) as domain.md says; if that should change too, it is a separate question.

## Acceptance criteria
- [x] API: in kid mode every shopping-list write is refused with `403 urn:foodplanner:problem:kid-mode` (add policy `FullSession` next to the group policy, no per-endpoint role code): generate, add weekly groceries, add and remove a manual item, check / uncheck, choose store, and the pantry writes (confirm, change, remove, clear). `GET` of the list, the chosen store and the pantry stay open. Adults and Child members outside kid mode are unchanged. OpenAPI lists the 403 on each; the TS client is regenerated. Integration tests for each write in kid mode and for a Child member outside kid mode; domain.md permissions updated
- [x] Kid list: big read-only item tiles with picture (or a section icon when there is none), checked items shown as done; no check-off, add, remove, generate, weekly groceries, pantry, export or store controls
- [x] Same live updates and offline cache as the adult list
- [x] Vitest and Playwright (mobile-390); `./scripts/verify.sh` green

## Roles (architect, 2026-11-03)
- **Kid mode** is for the smallest children (toddler / preschool): look only, pick dinners within the rules, like photos. Read-only shopping list as above.
- **Child member** (older child with their own login): may do close to what an adult does on the list and pantry (today's rights stay), but never anything that shops or triggers an order, e.g. sending to the Oda cart or ordering (see T-053). Any later task that loosens Child rights must keep that line.
