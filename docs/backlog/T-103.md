# T-103: Kid mode is confined to the profile's own household

Status: in-progress
Milestone: M1
Agent: implementer-backend
Depends on: T-026
Migration: no
Branch: task/T-103-kid-mode-own-household

## Goal
Architect decision Q-026 (option 2, 2026-11-01): while a device is in kid mode, the account can reach only the kid profile's household. Every other household of the account (e.g. grandparents' household where the parent is a support member) answers as if the account were not a member, for HTTP endpoints and SignalR hub groups alike. The household list in kid mode shows only the profile's household.

## Context
docs/questions/Q-026.md, docs/specs/T-026-kid-profiles.md, the T-026 review notes in docs/backlog/T-026.md. The check belongs where `HouseholdRoles.Effective` is applied: `HouseholdContextMiddleware` and `HouseholdMembershipGuard`, plus the household listing. Compare the route household with the `fp:profile-household` claim.

## Acceptance criteria
- [ ] In kid mode, every household-scoped endpoint of another household of the account answers the same as for a non-member (same status and problem type), tested across the endpoint enumeration used by `KidModeTests`
- [ ] A kid-mode hub connection cannot join another household's group of the account
- [ ] `GET /households` in kid mode lists only the profile's household
- [ ] Unlocking with the PIN restores access to all the account's households
- [ ] `./scripts/verify.sh` green; e2e with `--workers=1` not regressed
