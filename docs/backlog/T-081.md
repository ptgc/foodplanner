# T-081: Recipe source can be a book or a website

Status: in-progress
Milestone: L3
Agent: implementer-backend
Depends on: T-075
Migration: no
Branch: task/T-081-recipe-source-book-or-website

## Goal
Architect decision 2026-10-27: a recipe's source can be a website (as T-075: link + name) or a book (no link). T-075 currently clears the name when there is no URL, so a cookbook can't be recorded (found when adding "Lettbåten" from «Kaptein Sabeltann – Matskatter fra De Syv Hav», Terje Formoe, Cappelen Damm).

## Context
Read CLAUDE.md, docs/questions/Q-018.md, docs/domain.md (Recipe source link T-075), src/Domain/Recipes/Recipe.cs (SetSource, DeriveSourceName), RecipeEndpoints, web recipe-detail/recipe-edit + source-link.ts. Prefer no migration: SourceName alone (≤ 200 chars) is a book/other source; SourceUrl + derived/explicit name is a website. If a structured book source (title, author, publisher, page) clearly needs columns, raise it in the report instead of adding a migration — T-076 holds the migration slot.

## Out of scope
ISBN lookup; covers; bibliography formats.

## Acceptance criteria
- [ ] API accepts a source name without a URL (stored and returned); URL rules from T-075 unchanged; clearing both still possible; validation ProblemDetails for length
- [ ] Recipe detail shows a book/other source as plain text ("Kilde: …" / "Source: …"), a website as the T-075 link; never a link without a safe http(s) URL
- [ ] Edit form lets the user choose "Website" (link + optional name) or "Book or other" (text), translated nb + en, 390px, 44px
- [ ] Tests: API (name-only stored, URL+name, clear, too long), Vitest (both display modes, form), Playwright (set a book source on a recipe and see it)
- [ ] After merge, the orchestrator moves Lettbåten's source from its description into the source field
