## Goal
Optional fallback after the rule-based importer: lines the rules can't resolve (unparsed, unmatched, unclear purpose/alternatives) are sent to an LLM that fills the same structured fields from T-076. The user still reviews every line before saving.

## Context
Q-017 chose rule-based only; Q-018 records that this task exists but is not scheduled. Before starting: architect decides provider (default: Claude via the Anthropic API), model, cost limits, and whether recipe text may leave the server. The API key lives only in user secrets / Key Vault (rule 7).

## Out of scope
Replacing the rule-based parser.

## Acceptance criteria
- [ ] Off by default; enabled per environment by config; works without it
- [ ] Only unresolved lines are sent; output validated against the catalog (never trusted blindly); results marked as AI-suggested in the review screen
- [ ] Per-household rate/cost limit; failures fall back to the rule-based result
- [ ] Tests with a fake LLM client; no real API calls in verify.sh
