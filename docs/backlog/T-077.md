# T-077: AI-assisted fallback for recipe import

Status: in-review (backend round; the UI round is still to do)
Milestone: M4
Agent: implementer-backend
Depends on: T-076
Migration: maybe (usage counters for the limits)
Branch: task/T-077-ai-assisted-recipe-import

## Goal
Optional fallback after the rule-based importer: lines the rules can't resolve (unparsed, unmatched, unclear purpose/alternatives) are sent to an LLM that fills the same structured fields from T-076. The user still reviews every line before saving.

## Context
Q-017 chose rule-based only; Q-018 records that this task exists but is not scheduled. Before starting: architect decides provider (default: Claude via the Anthropic API), model, cost limits, and whether recipe text may leave the server. The API key lives only in user secrets / Key Vault (rule 7).

## Out of scope
Replacing the rule-based parser.

## Decisions (Q-028, architect 2026-11-08, option 1 on all)
- Provider and model: Claude Haiku 5.5 (`claude-haiku-5-5`) via the Anthropic API; the model id is in config.
- Data: only the unresolved ingredient lines leave the server (not the whole page, no user or household data), and only where the feature is on. The privacy text says unresolved import lines may be sent to Anthropic.
- Limits: per household at most 20 AI calls a day and 200 a month; one batched call per import; a global monthly cap in config. At a limit the import falls back to the rule-based result with a note.
- Where it is on: off by default everywhere; on locally (key in .NET user secrets, set by the architect) and in test (Key Vault reference, no deploy by agents); prod only after the architect decides.

## Plan
Backend first (config and options, Anthropic client behind an interface with a fake for tests, the batched call after the rule-based parse, catalog validation, AI-suggested marks in the import draft, per-household and global limits; a migration only if usage counting needs a table), then the UI round (AI-suggested marks and the limit note in the review screen, privacy text). No real API calls in verify.sh or e2e.
