## Goal
Add an automated accessibility check that catches problems lint and role-based tests miss, such as colour contrast, missing labels, duplicate ids and landmark errors. It runs on every main screen.

## Context
- Decided by the architect on 2026-11-24. This answers the open "axe" choice in T-117: add it.
- What exists today: `eslint-plugin-jsx-a11y` in `npm run lint`, and tests that find elements by role and accessible name. The `frontend-screen` skill says "There is no axe dependency". T-119 left its axe check open.
- e2e runs on Playwright (`tests/e2e`, `@playwright/test` 1.64.1) and always with `./scripts/e2e.sh --workers=1`.
- Recommended: `@axe-core/playwright` in the e2e suite (a dev dependency, so no web bundle cost). Each main screen is scanned at 390px with the WCAG 2.1 A and AA tags. The scan also covers kid mode and an open dialog or sheet where the screen has one.
- The main screens are the week plan, recipes list, recipe detail, recipe edit, import review, "Fra bilde", shopping list, Oda choices, household and members, account, privacy, sign-in, kid mode and support.
- Pin the exact version. Do not add axe to Vitest or the production bundle.

## Out of scope
Fixing a large number of violations. Fix the small ones in this task. When fixing would need a design choice (contrast, colours), record it in a follow-up task linked to T-134 (design update), and skip only that rule on that screen, with the follow-up task id in a comment.

## Acceptance criteria
- [ ] `@axe-core/playwright` (exact version) added to `tests/e2e`
- [ ] A shared helper, for example `expectNoA11yViolations(page)`, runs axe with WCAG 2.1 A/AA tags and prints readable violations on failure
- [ ] Every main screen listed above is scanned at 390px, including kid mode and at least one open dialog
- [ ] Violations fixed, or skipped per rule and screen with a linked follow-up task (no blanket disable)
- [ ] `frontend-screen` skill and `web/README.md` updated: new screens must add an axe scan
- [ ] `./scripts/e2e.sh --workers=1` and `./scripts/verify.sh` green

## Verification
The verifier removes a label or lowers a contrast on one screen locally and sees the axe test fail with a clear message, then restores it.
