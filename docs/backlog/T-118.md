## Goal
Architect request 2026-11-22: an Adult uploads one or more photos of a recipe (cookbook page, printout, handwritten card); Claude reads them and fills a recipe import draft (title, servings, times, ingredients as quantity + unit + catalog ingredient + note, steps, the book's tip as description, source book, and a cropped dish picture when the page has one). The household checks the draft in the existing import review before anything is saved. It must work for any book, not just the one used in chat.

## Context
Read Q-034 (answer), CLAUDE.md (rule 5: structured ingredients; rule 6: OpenAPI), docs/domain.md "AI-assisted import fallback", T-075, T-077 (`AnthropicRecipeLineAi`, `AiImportOptions`, `AiHouseholdUsage`), and the claude-api guidance for C# (prefer the official Anthropic C# SDK over raw HTTP; structured outputs for the draft; check `stop_reason`, including `refusal`).
- The "skill": a versioned instruction file `src/Infrastructure/Import/Ai/Skills/recipe-from-photo.md` (rules only, no book text), used as the system prompt.
- Ingredient rules (architect 2026-11-22): a variant goes to the base ingredient with a note (småpoteter → Potet, torskeloin → Torsk, kremfløte → Fløte); real product differences stay separate (røde vs grønne linser, cayennepepper vs pepper). Unknown ingredients are proposed as new, never invented silently.
- Uses the shared app key for every household (Q-034 answer: own keys postponed, T-120), with a configurable per-household daily limit for photo imports (default 2) and a global monthly cap; records input/output tokens per call for T-121. Start with Claude Opus 5.5; the eval compares Haiku 5.5, Sonnet 5.5 and Opus 5.5 once.
- Photos are sent to Anthropic: the privacy page (T-113/T-117) must say so before this ships.
