## Goal
Give the API a database connection without any schema yet: Microsoft.EntityFrameworkCore.SqlServer, an empty AppDbContext in Infrastructure registered through AddInfrastructure, `ConnectionStrings:Default`, and `GET /api/health/ready` that reports whether SQL Server is reachable. `GET /api/health` stays database-free (T-002 contract).

## Context
Read CLAUDE.md, docs/domain.md and relevant ADRs in docs/adr/. AppDbContext here is a shell. T-008 extends it with tenancy and T-009 with Identity, so keep it minimal and in `Foodplanner.Infrastructure.Persistence`. No password goes in the repo (CLAUDE.md rule 7). In Development the API gets `ConnectionStrings:Default` from .NET user secrets (UserSecretsId in the Api csproj); in containers from the `ConnectionStrings__Default` env var. Never fall back to a default password.

## Out of scope
Entities, migrations, tenancy (T-008), Identity (T-009), Testcontainers.

## Acceptance criteria
- [x] `GET /api/health/ready` returns 200 `{ status: "Healthy", database: "Up" }` against the compose SQL Server
- [x] With SQL stopped it returns 503 ProblemDetails, not an unhandled exception
- [x] A test proves the 503 path quickly (unreachable server, 1 second connect timeout, test finishes in under 10 seconds)
- [x] AppDbContext has no entities and there are no migrations; `/api/health` still works with SQL stopped
- [x] Api csproj has a UserSecretsId; no SQL password or password-bearing connection string exists in any tracked file
- [x] A missing connection string makes `/api/health/ready` return a clear 503 ProblemDetails, not a crash and not a default password
- [x] `dotnet ef` is not required to run the app; the database itself is created by compose sql-init (T-003)

## Verification
`./scripts/verify.sh` green, plus the checks above evidenced in tests or PR notes.
