# Q-016: Store the registration time as a column instead of an Identity claim?
Raised by: orchestrator (from review of T-072) / affects T-072 cleanup job
Status: answered

## Context
T-072 deletes unconfirmed accounts after the confirmation window. AspNetUsers has no created-at column, and adding one needs a migration (rule 9), so T-072 stores the registration time as an Identity user claim `foodplanner:registered-at` (zero-padded unix seconds) in AspNetUserClaims. It works and is tested, but AspNetUserClaims is only indexed on UserId, so the cleanup query scans all claims every 15 minutes, and the claim is remove-then-add rather than a single column update.

## Options
1. Keep the claim. Fine at family scale; revisit if the claims table grows.
2. Follow-up task with a migration: add `AspNetUsers.RegisteredAt` (datetimeoffset, indexed, filtered on unconfirmed), backfill from the claim, switch the cleanup query, drop the claim.

## Recommendation
Option 2 as a small task before any deployment beyond local; option 1 is fine for L2.

## Answer (architect)
Option 2, decided by the architect on 2026-10-25: add AspNetUsers.RegisteredAt (indexed), backfill from the claim, switch the cleanup job, drop the claim. Implemented by T-074.
