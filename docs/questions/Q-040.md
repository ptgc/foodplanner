# Q-040: Does searching every recipe ingredient fit Oda's terms for "own shopping" (T-130)
Raised by: spec-writer / task T-130
Status: open

## Context
Oda's terms (`spikes/oda/findings/tos-mcp-section.md`, Q-024) say the user may use the connection only for their own shopping and must not extract or collect products, prices or other content beyond what that shopping needs. The Q-024 answer (2026-11-20) allowed the household's shared account for "Add to Oda cart" and noted: "search only for the items being added, with no product or price collection beyond that." T-130 (architect request 2026-11-22) searches Oda for all ingredients used in the household's recipes, not only the items of one shopping list, so that the household can choose preferred products once. The spec keeps this narrow: it is started by an Adult, only the household's own ingredients are searched (no crawling, no result pages beyond page 1), only product ids are stored and only the ones the user ticks, names, prices and hit lists are not stored or logged, and a 429 is never worked around. Whether that still counts as "what their own shopping needs" is a legal and product judgement.

## Options
1. Proceed as specified; treat it as the household's own planned shopping (these are the ingredients of meals they plan to buy), with the narrow limits above, and record the reading in the T-130 PR notes. If Oda objects, the feature is switched off with `Oda:ClientId` or a feature flag.
2. Proceed, but limit each run to ingredients of recipes planned in the coming N weeks (for example 4) instead of all recipes. Closer to "items being bought", but the user must plan first and the feature loses much of its "set up in one go" value.
3. Ask Oda in writing (the route Q-024 option 1 offered) before shipping T-130. Safest; T-130 waits for the answer.

## Recommendation
Option 1. The searches are the same kind and size as a weekly fill, are triggered by the user for their own recipes, and nothing but the chosen ids is kept. Add a kill switch (the existing `Oda:ClientId` empty setting already hides the feature) and mention the reading in the PR notes so the architect can revisit it after the real-Oda try-out. Option 3 stays available if the architect wants certainty.
