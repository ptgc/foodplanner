# Q-026: Is kid mode limited to the kid profile's own household?
Raised by: reviewer / task T-026 (2026-10-31)
Status: answered

## Context
T-026 implements the spec: kid mode makes the account's effective role Child in **every** household the account belongs to. If a parent is Adult/Owner in household A (where the kid profile lives) and also in household B (e.g. grandparents' or a holiday household), a kid on that device can, in household B, do what a Child member can: add dinner picks (not attributed to any profile, so the kid cannot change them afterwards), check off and add shopping items, generate the shopping list, confirm pantry items. Nothing Adult-only is reachable. Most families have one household, so this only matters for accounts in several households.

## Options
1. Keep as is (Child-level access in all the account's households) and document it.
2. Confine kid mode to the profile's household: other households answer 403/404 while in kid mode (a check where `Effective` is applied, in `HouseholdContextMiddleware` and `HouseholdMembershipGuard`). Small backend change plus tests; the kid screens (T-091) then only ever show one household.

## Recommendation
Option 2: the kid profile belongs to one household, and a kid has no reason to touch another household's list. It is a small change; do it as a follow-up before or with T-091.

## Answer (architect)
Decided by the architect on 2026-11-01: option 2. A kid profile only reaches its own household; kid mode must not reach the parent's other households (a parent can be a member elsewhere, e.g. as support for grandparents). Implemented as T-103, before T-091.
