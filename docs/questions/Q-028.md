# Q-028: AI fallback for recipe import (T-077)
Raised by: orchestrator / task T-077
Status: open

## Context
T-077 sends the import lines the rule-based importer cannot resolve (unparsed, unmatched, unclear purpose or alternatives) to an LLM, which fills the same structured fields; the user still reviews every line, and the output is checked against the catalog. Q-017 chose rule-based only and Q-018 parked this task. Before building, four decisions are needed.

## 1. Provider and model
1. **Claude via the Anthropic API, a small fast model (Haiku 5.5, `claude-haiku-5-5`) for line parsing**, with the model id in config so it can be changed without code.
2. Claude Sonnet 5.5 (better on messy text, about 3x the cost).
3. Azure OpenAI (keeps data inside the Azure tenant).

Recommendation: 1. The task is small, structured extraction; Haiku is enough and cheap.

## 2. May recipe text leave the server
1. **Yes, only the unresolved lines (ingredient text, not the whole page, no user or household data), and only when the feature is turned on for the environment.**
2. Yes, the whole recipe text (better context, more data sent).
3. No (then T-077 is cancelled).

Recommendation: 1. Note in the privacy text that unresolved import lines may be sent to Anthropic.

## 3. Cost limits
1. **Per household: at most 20 AI calls a day and 200 a month; one call per import (all unresolved lines batched); a global monthly cap in config. When a limit is reached the import falls back to the rule-based result with a note.**
2. No per-household limit, only the global cap.

Recommendation: 1.

## 4. Where it is on
1. **Off by default everywhere; on locally (with the key in user secrets) and in test (Key Vault); prod only after you decide.**
2. On in all environments once built.

Recommendation: 1 (rule 7: the API key lives only in user secrets / Key Vault).
