# Q-015: Close the revoked-member window on realtime connections
Raised by: orchestrator (from review of T-034) / affects T-034, T-044, T-048
Status: open

## Context
T-034's SignalR hub checks the cookie only when a connection opens and checks household membership on every join and state request. A connection that already joined a household group keeps receiving that group's change signals until it disconnects, even after the member is removed, logs out, changes password or is disabled. The signal is content-free (`{householdId, weekStart, kind, itemId}`); reading the list still requires a fresh membership check, so no list content leaks. Today nothing removes members (that is T-044/T-048), so the window cannot be triggered yet.

## Options
1. Accept for now; revisit in T-044/T-048 when member removal exists.
2. Evict on change: when a membership is removed (T-044/T-048) or the security stamp changes (logout everywhere, password change), remove that user's connections from the household group and abort them (track connection ids per user).
3. Cap connection lifetime (e.g. re-authenticate every 15 minutes by closing connections server-side; clients reconnect and re-check).

## Recommendation
Option 1 now, and make option 2 an acceptance criterion of T-044/T-048. Option 3 as a cheap backstop if option 2 slips.
