# Q-031: Web bundle size budget
Raised by: orchestrator / tasks T-095, T-100
Status: answered

## Context
`web/scripts/check-bundle-size.mjs` enforces `{ initial: 135, firstLoad: 159, total: 234 }` KB (gzip; see web/README.md). After T-110 the total is 233.4 KB, so any new screen (T-095 delete account, T-100 what can I make) goes over.

## Options
1. **Raise the total to 250 KB; keep initial at 135 KB.** New screens are lazy chunks, so phones do not load them until opened.
2. Shrink existing code first (separate task), keep 234 KB.
3. Raise a little per task, with the architect's OK each time.

Recommendation: 1.

## Answer (architect)
Answered 2026-11-08: option 1, and a standing rule for later tasks:
- Total budget 250 KB now; initial (135 KB) stays as it is.
- Sizes will fluctuate: the orchestrator may raise the total (and firstLoad) a little when a task needs it, without asking each time. Keep the first load quick: keep initial tight and prefer lazy chunks for new screens.
- If a task would need a big increase, make the change anyway and add a cleanup task to shrink the size later.
- Each raise is recorded in web/README.md (the budget table) and the task's Result.
