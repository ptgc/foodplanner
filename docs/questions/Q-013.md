# Q-013: Language of the app and of catalog data
Raised by: orchestrator / task T-020 (affects T-024, T-025, T-035, T-036 and Oda mapping T-052)
Status: answered

## Context
T-020 seeds ~100 "common Norwegian-kitchen ingredients" and nothing decides their language. The UI built so far (T-004, T-028) is in English ("API is Healthy", "Log out"). The users are Norwegian families and the shopping integration is Oda (Norwegian product names). To avoid blocking L2, T-020 seeds names in Norwegian bokmål from a single data file so they are cheap to change.

## Options
1. Norwegian bokmål everywhere: UI text and catalog names. Simplest; matches the users and Oda.
2. Norwegian catalog names, English UI for now; translate the UI later.
3. Bilingual from the start: catalog rows carry nb and en names, UI uses a small i18n layer (e.g. a messages file per locale). More work in every frontend task.

## Recommendation
Option 1 for the product, but keep UI strings in one place per screen so option 3 stays possible. Until answered: catalog in bokmål (T-020), UI text stays English.

## Answer (architect)
Decided by the architect on 2026-10-24: all user-facing text is translatable. Code, keys and fallback are English. Locales for now: nb and en. If a translation is missing the short English text/key is shown. Seeded catalog data (global ingredients, units, tags) is translatable too (nb + en); text a household types itself stays as typed. Implemented by T-038 (UI) and T-039 (catalog data).
