# Q-004: How a request carries its household context
Raised by: spec-writer / task T-011 (pattern copied by every household-scoped endpoint)
Status: answered

## Context
ADR 0005 says the EF global query filter is driven by `ICurrentHousehold`. T-011 must implement `ICurrentHousehold` and "active household selection", and a user can belong to several households. Nothing decides how the API learns which household a request is for. Every later endpoint (recipes, plans, lists), the SignalR hubs (T-034) and the generated TS client copy this choice, so it is hard to change later.

## Options
1. **Route segment.** Household-scoped endpoints live under `/api/households/{householdId}/...`. An endpoint filter on that group resolves the membership and populates `ICurrentHousehold`. "Active household" is a client-side choice; the SPA remembers the last one used. Trade-off: longer URLs, and every scoped endpoint has the parameter. In return it is explicit, works with two tabs open on different households, maps naturally to SignalR groups, and shows up in OpenAPI.
2. **Request header.** The client sends `X-Household-Id` on every scoped request, and middleware resolves it. Trade-off: URLs stay short, but the context is invisible in URLs and logs unless added, the generated client has to inject the header, and browser navigations or SignalR negotiate need special handling.
3. **Server-side active selection.** `PUT /api/me/active-household` stores the choice in the auth cookie (a claim, with the cookie re-issued) or on the user row. All later requests use it implicitly. Trade-off: simplest client, but two tabs or devices on different households interfere, a switch must refresh cookies, and a stale selection after removal from a household needs extra handling.

## Recommendation
Option 1. Explicit context per request removes a class of "wrong household" bugs. It is safe across tabs and devices, and it is easy to test and to authorize with policies. "Active household selection" becomes the SPA's remembered default, plus `GET /api/households` to list choices.

## Answer (architect)
Decided 2026-10-22: option 1. Household-scoped endpoints live under /api/households/{householdId}/... and an endpoint filter on that group populates ICurrentHousehold. 'Active household' is a client-side choice; the SPA remembers the last one used. Every later household-scoped endpoint follows this.
