# Q-037: Official Anthropic C# SDK for the new photo call: only the new call, or also T-077's line help?
Raised by: spec-writer, task T-118 (docs/specs/T-118-recipe-from-photo.md)
Status: answered

## Context
T-077 calls Claude with raw HTTP (`AnthropicRecipeLineAi`), hardened and tested (no redirects so the key cannot be re-sent, https base URL rule, `OutboundHttpRulesTests`, response size cap). The task file prefers the official Anthropic C# SDK for new code. The photo call needs image content blocks, structured outputs (`output_config.format`), `output_config.effort`, `stop_reason` handling and token usage. Adding a NuGet dependency and a second way to call the same API is an architecture choice (no ADR covers it).

## Options
1. **SDK for the new photo call only; T-077's call stays raw HTTP.** No risk to the verified T-077 path; two clients exist for a while. The SDK is configured with no automatic retries (a retry would double the cost) and the fixed base URL; a new architecture rule keeps SDK types inside `Infrastructure`.
2. SDK for both calls in T-118. One client, one set of hardening rules; but T-118 then changes a merged, verified feature and its tests (`AnthropicRecipeLineAiTests`, hardening tests) and grows.
3. Raw HTTP for the new call too (no new dependency). Same pattern as today; more hand-written JSON for images and structured output, and the SDK's typed usage and stop reasons are lost.

## Recommendation
Option 1. Move T-077 to the SDK in a separate small task later (not scheduled), when its code is next touched.

## Answer (architect)

Answered 2026-11-22 by the architect: go with the recommendation.
