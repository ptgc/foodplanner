# Q-007: Production email provider
Raised by: architect / task T-017
Status: open

## Context
Q-002 option 1 needs real confirmation emails before families can register locally in a deployed environment. T-009 only builds the IEmailSender port and a recording sender. Azure is the hosting platform, credentials must come from Key Vault or managed identity (rule 7), and message volume will be tiny.

## Options
1. **Azure Communication Services Email.** Same cloud and billing as the rest, can be provisioned in Bicep. Needs a verified sender domain (DNS records). Trade-off: more setup, and I have not verified its current authentication options or pricing.
2. **A transactional email service (for example SendGrid, Postmark or Mailgun).** Quick to set up with a free or cheap tier, good deliverability tooling. Trade-off: another vendor and an API key in Key Vault.
3. **Plain SMTP relay** (for example the family's own mail host). Least new infrastructure. Trade-off: deliverability and credential handling are on you.

## Recommendation
Option 1, if its managed-identity support and cost check out; otherwise option 2. Verify current pricing and auth options before committing.
