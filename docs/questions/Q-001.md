# Q-001: Task branches and the fate of main
Raised by: architect / task T-063
Status: open

## Context
Branches dev, test and prod exist (all at the initial commit) alongside main. Agents may push directly to dev; the architect promotes dev to test to prod by PR. CLAUDE.md rule 8 still says one task = one branch = one PR, and the orchestrator is told never to merge to main.

## Options
1. Task branches stay. Agents work on `task/T-xxx-slug`; the orchestrator merges into dev after green CI, verifier and reviewer approval, without a PR. CI also runs on push to dev.
2. Agents commit straight to dev, one commit per task, running verify.sh first. Least ceremony, but parallel tasks can collide and dev can break.
3. Task branches with a PR into dev per task, merged by the orchestrator once gates pass. Keeps the PR template and CI-on-PR (T-005), most ceremony.

For main: (a) delete it and make dev the default branch, or (b) rename it to prod and drop the separate prod branch.

## Recommendation
Option 1 with main deleted (a). It keeps tasks isolated and dev always green, while honouring direct pushes to dev.
