# Q-010: Scope and rules for local iteration L2 (recipes to shopping list)
Raised by: orchestrator / L2
Status: answered

## Context
After L1 the architect asked for a bigger local batch: from login and households to recipes in the browser with data from the database, and on to a shopping list generated from one or more recipes. Still local only. Several things were not settled by the backlog: how to log in without Google (T-010), the missing login screen, how migrations reach the local database, and the merge gate.

## Options
1. Seeded local admin (credentials in user secrets) + email/password login; new tasks T-028 (login screen) and T-029 (local migrations + seeded admin); full gate on auth/tenancy, light gate elsewhere.
2. Email/password only, register yourself; no new tasks; full gate everywhere.
3. Defer: finish M0 only.

## Recommendation
Option 1.

## Answer (architect)
Option 1, decided by the architect on 2026-10-23 in the orchestrator session:
- Scope L2: T-008, T-009, T-011, T-029, T-012, T-027, T-028, T-020, T-021, T-022, T-023, T-024, T-025, T-031, T-032, T-030, T-033, T-034, T-035, T-036.
- Postponed: T-010 (Google login). Out: Azure tasks (T-006, T-007, T-016), T-013, T-005, T-026, T-037 and later.
- Local only. Every secret (SQL SA password, seeded admin) lives in .NET user secrets on the developer machine, never in the repo.
- Seeded local admin instead of Google login: user + household "Home" as Owner, Development only (T-029).
- New login screen task T-028.
- Merge gate: full ADR 0009 gate (verifier + reviewer, reviewer on opus, implementer on opus for T-008) for T-008, T-009, T-011, T-012. Light gate (implementer evidence + orchestrator-run verify.sh on dev, as Q-009) for the rest.
- Tasks without a spec use their acceptance criteria as the spec.
