# Q-034: Claude in the app: recipe from a photo, whose key, limits, model, and the "skill"
Raised by: orchestrator, architect request 2026-11-22 (tasks T-118, T-119, T-120, T-121)
Status: open

## Context
The architect wants households to add recipes by uploading a photo of a cookbook page, the way the 17 «Kaptein Sabeltann» recipes were added in chat on 2026-11-22. Claude reads the photo and fills a recipe draft that the household checks before it is saved. Wishes:
- A household can use its own Claude connection.
- A shared app connection that everyone can fall back to, with a strict limit (for example 2 photo imports per household per day).
- An app admin (T-096) who gets emails with chosen metrics, among them how much the app spends on Claude.
- A "skill" that holds how to read recipes, taught with examples from several books, not just one.

What exists: T-077 already calls Claude (`AnthropicRecipeLineAi`, raw HTTP, model `claude-haiku-5-5` in `AiImportOptions`) for unresolved import lines, with the app's key and per-household day/month limits (`AiHouseholdUsage`) and a global monthly cap. The import review screens (T-075, T-077) already let a household check a draft before saving.

Fact to know: a household's "own Claude connection" for an app means an Anthropic API key from the Claude Console (pay as you go). A Claude.ai subscription (Pro/Max) cannot be used by another app.

## Options

### A. Keys and limits
1. Shared app key only, with per-household limits.
2. **Shared app key as the fallback with a small per-household limit (default 2 photo imports per day, plus a global monthly cap), and optionally the household's own Anthropic API key, which removes the shared limit for that household.** The own key is stored encrypted (T-099: application-level encryption, keys in Key Vault), never shown again after saving, and can be removed.
3. Own key required; no shared connection.

### B. Model for photo reading
1. Claude Haiku 5.5 (what line help uses today; about $0.10 / $0.50 per million tokens; well under 1 US cent per photo).
2. Claude Sonnet 5.5 ($2 / $10).
3. Claude Opus 5.5 ($4 / $20; roughly $0.03-0.06 per photo, so about $2-4 (20-40 kr) per household per month if the 2-a-day limit is used every day).
Photos with small print, rotated pages and handwritten notes are where the models differ.

### C. What the "skill" is
1. **A versioned instruction file in the repo (`src/Infrastructure/Import/Ai/Skills/recipe-from-photo.md`): how to read a recipe page (title, servings, ingredients as quantity + unit + name + note, steps, tip as description, source book), the ingredient rules (variant → base ingredient with a note, real product differences stay separate: røde vs grønne linser, cayennepepper vs pepper), and output through structured outputs so the result always fits the import draft.** Taught by an example set (photo + the correct recipe) used by an eval script that scores every change to the file.
2. Anthropic "Agent Skills" over the API (a container with code execution). More moving parts and cost; not needed for one extraction call.

### D. Teaching examples from books
1. **Photos and the correct recipes are kept locally, outside git (a gitignored folder), because they are copyrighted book pages; the skill file holds only general rules learned from them.**
2. Commit the examples to the repo.

### E. Admin metrics
1. **A small metrics job: count per day (AI calls and tokens per household and in total, estimated cost, photo imports, new households/recipes); the app admin chooses which metrics and how often (daily or weekly email).** Needs the app admin (T-096) and the email provider (T-017, blocked).
2. Use Anthropic's own usage and cost reports (Console / Admin API) instead of counting in the app. Only covers the shared key, not households' own keys.

## Recommendation
A2, C1, D1, E1 (with Anthropic's cost report as a cross-check of the shared key). For B: build the example set first, then run it once on all three models (a few kroner) and choose; until then use Claude Opus 5.5 for photos, since the shared limit keeps the cost small and reading quality matters most. Order: T-118 (photo import with the shared key and its limit) → T-119 (upload screen) → T-120 (own key, needs T-099) → T-121 (admin metric emails, needs T-096 and T-017).
