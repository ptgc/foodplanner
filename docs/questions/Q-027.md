# Q-027: Deleting a user account (T-095)
Raised by: orchestrator / task T-095
Status: open

## Context
T-095 adds "delete my account" (and later a system-admin delete, T-096) and uses it to clean up the e2e test users. Today a user's rows point at the account in several places: memberships (cascade), meal plan picks, who checked a shopping item, pantry confirmations, week lock, invites created (Restrict), recipe imports (`CreatedByUserId`, NO ACTION), kid profiles and their PIN/likes. docs/domain.md says account deletion must never orphan a household (its last Owner) and must deal with the NO ACTION/Restrict keys first. Four points need a decision.

## 1. Households the user owns
1. **Refuse while the user is the only Owner of a household that has other members** ("transfer ownership first", T-048). A household where the user is the only member is deleted together with the account, after an explicit confirmation listing those households.
2. Refuse for any owned household, even one with no other members (user deletes those first by hand).
3. Auto-promote the oldest Adult to Owner.

Recommendation: 1 (matches the T-095 criterion; option 3 hands power to someone without their consent).

## 2. Their history in households that live on (picks, checked items, pantry confirmations, week lock, imports, invites)
1. **Keep the rows, drop the link to the person**: the user id is set to null (or a fixed "deleted user" marker) and the UI shows "Deleted user". Open invites they created are revoked; their recipe imports (drafts) are deleted. Needs nullable columns, so **a migration**.
2. Delete the rows the user created (their picks disappear from plans, checks become unchecked).
3. Keep the user id but scrub the identity (email/name replaced, login removed); no schema change, but a "zombie" identity row stays.

Recommendation: 1 (the family's plans and lists stay intact, no personal data left; the migration is small). Option 3 is the fallback if you want no migration now.

## 3. How final, and how is it confirmed
1. **Immediate and permanent**, after re-entering the password (or a fresh Google sign-in) and typing a confirmation; sessions on all devices are signed out. No grace period.
2. Soft delete with a 30-day grace period, then a background job purges.

Recommendation: 1 for now (no background jobs exist yet; GDPR erasure is satisfied by actually deleting). A grace period can come later.

## 4. Data export before deletion
1. **Offer the existing household export (T-044) as a link on the delete screen; no new personal export.**
2. Add a personal data export (everything about the user) first.

Recommendation: 1.
